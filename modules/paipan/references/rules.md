# 奇门九宫排盘 · 引擎0.4.1／输出工具0.5.0

默认目标仍是所提供的正易奇门 1.9.8 恢复设置后选择“时家／转盘／拆补”。本版支持时家、日家、月家与转盘、飞盘、星飞门转、神转飞盘；时家支持拆补／置闰，合计16种组合。七项设置按各层适用范围调用。计算程序和界面均为独立实现，APK 仅在开发阶段作为规则及输出参考，不复制、翻译其实现，也不加载原库参与运行。

## 默认方式与选择流程

本 skill 默认使用 **时家转盘拆补，寄宫法为寄坤二宫，九星顺逆选项为阳顺阴逆**。用户未指定流派时直接采用默认，只询问缺少的日期或时间。已明确指定的流派和设置优先；用户想切换但尚未选择时，列出时／日／月家、转盘／飞盘／星飞门转／神转飞盘，以及时家拆补／置闰等已实现选项，等待用户选择，不代替用户决定。

用户选择非默认流派或要求自定规则后，必须继续收集适用且尚未明确的下一级设置；只有获得选择或“其余默认”等授权后才起最终盘。完整分流、依赖、可选值及命令行参数集中在 [settings.md](settings.md)，保持该文件为设置询问依据。

九星顺逆选项只在九星飞布时生效；默认转盘沿外圈转布，不调用该飞布方向选项。当前“阳顺阴逆”默认值是用户指定的配置，不应混同于原 APK 通用星向的默认顺飞。

## 使用

由 skill 输入公历年月日时分和明确方法，使用脚本返回路径打开 HTML。正常排盘生成 JSON、HTML、Markdown，并按原方式尝试 PNG。HTML 内嵌原始快照、原创引擎与节气表，断网可用；初始显示不重新计算。交互按时间起局推四柱和定局；按局复核给阴阳、局数、起盘干支，季节寄宫需选节气。点九宫看各层元素，保留紧凑配对布局与保存当前盘文／打印。

代码结构按“历法 → 所选时间层级定局与起盘柱 → 星干门神各层飞转 → 九宫结果与计算步骤”组织。传统宫序、名称、局数表与干支规则是规则数据，不能称为我们发明；本次原创的是程序实现。网页版计算全在本机，没有服务器后台或远程排盘接口。

### 鸣法暗干中的甲时

该分支的暗干使用乙至癸九干循环，没有单独占宫的甲。设时干序号为 `s`（甲 0 至癸 9），时支序号为 `b`（子 0 至亥 11），旬首仪的**原宫**为 `a`，当前宫为 `p`，阳遁方向 `d=1`、阴遁 `d=-1`：

```
暗干序号 = 正模(s - 1 + d × (p - a), 9) + 1
暗支序号 = 正模(b + 暗干序号 - s, 12)
```

这里的“正模”返回非负余数。这是从 APK 该函数输出归纳并通过全部 1,080 个测试盘的公式，不应直接当作所有流派都一致的暗干法。例如阳遁一局甲子时，坎一宫在这个软件分支中得到暗干支“癸酉”。中宫作为锚点时仍用原中五宫数，不先改为所选寄宫。



## 新增盘式、日家与月家

| 盘式 | 九星 | 天盘干 | 门 | 神 |
|---|---|---|---|---|
| 转盘 | 转 | 转 | 转 | 转 |
| 飞盘 | 飞 | 飞 | 飞 | 飞 |
| 星飞门转 | 飞 | 飞 | 转 | 飞 |
| 神转飞盘 | 飞 | 飞 | 飞 | 转 |

各层单独决定飞转，保持同一地盘、旬首原宫和起盘干支。星飞、干飞沿九宫数排布；门转沿外圈，旬首或目标中五先按所选寄宫处理；神转起点遇中五也按寄宫处理。中门只参与门飞的两种盘式，太常只参与神飞的两种盘式。九星方向只参与星飞，神名替换只参与阳遁神转。

时家按时柱起盘，拆补及置闰规则沿用下文。日家以日柱代入旬首、值符、值使等核心排布；月家以月柱代入；真实四柱仍按同一历法输出。JSON `activePillar/activeGanZhi/activeIndex` 明确实际起盘柱，`hour/hourIndex` 保留真实时柱。

日／月家不调用时家拆补／置闰或置闰天数。网页定局栏显示“日家定局／月家定局”，不能任意组合成“日家置闰”。这对应 APK 主入口中定局被专用函数覆盖的路线。

### 日家定局

节气索引从冬至0至大雪23。年支取子0至亥11，冬至／小寒／大寒加2，其余加1；超过12回到1，所得数 `b<7` 为阳，其他阴。元序 `floor((节气索引 mod12)/4)`。局表行：前十二节气取 `2b−2`，后十二节气取 `2b−1`；派生定局标签行 `2b−2+(阳?1:0)`。查同一三元局数表。

### 月家定局

采用输入公历年；冬至至大寒加1，其余不变。`n=max(1,ceil((修正年−1884)/5))`；元序 `n mod3`；局表行 `(9+floor(n/3)) mod24`，前十二行阳、后十二行阴。使用同一局数表。

派生定局节气是该软件的定局标签，不是当前交节。**日／月家季节寄宫使用真实当前节气；时家置闰使用置闰定局节气。** 分别输出 `dingJu.term`、`solar.current.term` 与 `hostTerm`，不把定局标签写进历法四柱。

### 新增验证与明确范围

- 混合盘默认：阴阳九局×六十起盘干支×两个盘式，共2160组。
- 混合盘设置：星向、门序、中门、太常、阳神名称，以及六种寄宫／季节／中五边界，共576组。
- 日／月家：1900、1955、1984、2026、2100年，年初、立春前后、23点及年尾，共240组专用定局后核心排布。
- 合计2976组，逐宫地干、天干、九星、门、天地神、寄干及禽标记，值符目标、值使记名和目标均一致。日／月定局另对288+1407=1695组函数输入核对一致。
- 日／月家整盘测试给原生步骤共同的分钟节气与四柱输入，验证其定局和选柱、排布组合，不宣称 APK 自己的历法已经完整交叉验证。
- 原软件的两种混合盘和日／月家使用另一套默认附干分支；本版不将时家鸣法套入。对应 `darkMode=unavailable`，暗干字段为空、显示开关禁用。它是尚未实现的附加层，不表示这些流派本身没有暗干。现有时家转盘／飞盘鸣法保持原验证范围。

## 历法与范围

数据按最近分钟保存，以该分钟起点交节。1898—2101 共 4,896 个时刻、33,658 字节，其中 1898 年只补置闰年初回溯所需资料；实际输入范围仍为 1900—2100，没有增加大型运行依赖。表格由开发时 JPL DE440s + Skyfield 1.55 计算，运行只需本地 JSON。与香港天文台 2019—2028 共 240 个时刻对照，239 个相同、1 个相差一分钟。

交节前后 3 分钟提示核对。分钟粒度不承诺全范围绝对误差小于一分钟。固定 UTC+8，不处理历史地方时或夏令时。置闰对上元基准的公历日敏感，临近 23 点的交节差异可能改变基准；比较软件时先统一历法和设置。年、月柱未做原软件全量对照，空亡驿马采用通行时柱规则。

当前不支持茅山、阴盘定局、年家、刻家、其他特殊预设、自定义分层寄宫、农历输入、真太阳时或其他日界；新增方法的专用附干层尚未接入。不含旺衰、十二长生、神煞、格局与吉凶解读。

## Skill 运行

`scripts/paipan.cjs` 使用 Node 内置模块，原引擎只算一次；新增输出层校验结果并生成 JSON、HTML、Markdown。`scripts/render_chart.py` 用已有 Python Playwright 和 Chrome／Edge／Chromium 渲染 PNG，不下载浏览器或星历。新版接口与状态见 [data-interface.md](data-interface.md)，导出规范见 [markdown.md](markdown.md)，可重复测试与回归基准见 [testing.md](testing.md)。这些工程改动未调整上述计算规则。
